## 2026-11-17 — v0.4.0 현장 피드백 반영 (미커밋, 보안 검토 대기)

- 작업자 화면: 작업선택·필드갱신·갱신후인쇄·인쇄신호 버튼 삭제 → **[데이터 전송]** 하나
- 작업은 입력하지 않고 **프린터에서 불러와 선택**(`~JR` 현재 작업 + 이 PC가 기억한 최근 작업, `job_picker.py`). 작업 목록 조회 명령은 NGPCL에 없음
- 필드이름은 입력하지 않음: 메세지를 추가한 순서대로 **text1, text2, text3…**(`messages.py`), 프린터 이미지의 필드 이름을 이렇게 만들어 두기로 약속
- 2차(관리자): 같은 작업 선택 + 같은 메세지 입력 → 일치하면 전송 → 결과 창에서 **[인쇄 시작](`~ST|06|`)·[정지](`~ST|11|`)** 선택, 보낸 데이터·프린터가 받은 메세지 표시. 기존 '전송 직후 자동 작업 시작'은 **삭제**(수동 선택). 시작/정지는 기록(`print_control`)에 남김
- 결과 창이 떠 있는 동안 작업 결과가 반영되도록 화면 갱신 큐 처리 수정(`app._drain`)
- 메세지 원문은 목록에 보관(표 값이 숫자로 바뀌어 앞의 0이 사라지는 문제 방지, 예 00123)
- 보안 검토 반영: 결과 창은 통신 중 X로 못 닫음·3분 뒤 자동 닫힘(로그아웃) · [인쇄 시작] 직전 되읽기 재확인 · 보내지 않은 text칸에 이전 값이 남아 있으면 노랑 · 인쇄 제어 기록 실패 표시. 남은 것: 전송 전에 프린터가 이미 생산 중이면 새 데이터가 바로 인쇄될 수 있음(기존 동작, 정지 후 전송 권장)
- 확인 필요: `~ST|11|`(정지=Held) 실장비 동작, 마스터 단독 인쇄 제어 여부, 작업 목록 조회 방법(서비스 매뉴얼)

## 2026-11-16 — 업그레이드 v0.3 작업 (미커밋, 보안 검토 대기)

원칙(사용자 지시): **통신 방식은 수정하지 않는다**(`ngpcl.py`·`dual.py` 그대로). 기능 추가만. 1대 제어를 확실히 하되 **장비 18대까지 확장**할 수 있게 새 모듈은 장비 연결에 의존하지 않는다(전송 함수 `xchg`만 받음).

추가된 것
- 수신 확인 신호등: 전송 성공 직후 `~FR`로 필드를 되읽어 초록/노랑/빨강 + "장비가 받은 값" 표 (`verify.py`, `verify_ui.py`, `confirm_ui._send`). 작업 로그·CSV에 "수신 확인" 열
- 필드 조회(`~FR`, 이름 비우면 전체) · 설정 조회(`~SR`) · 설정 변경(`~SC`) — `device_tools.py`, TTO 화면 "필드·설정 조회" 카드
- **설정 변경은 이중 입력(대표님 결정 2026-11-16)**: 작업자가 이름·값 요청 → 관리자(또는 마스터)가 같은 이름·값을 입력해 일치할 때만 전송 → 변경 후 `~SR` 되읽기 신호등. 불일치 3회 규칙·10분 만료·1회용 승인표 모두 동일. 작업 로그에 종류 "설정 변경", 데이터 `이름=값`, 수신확인 `이전 → 이후`. `dual.py`에는 종류 `setting` 추가만(기존 동작 불변), `dual.run`은 `setting`을 실행하지 않고 전용 경로(`confirm_ui._send_setting`)로만 전송. 마스터 단독 `~SC` 경로는 삭제(아래 검토 지적 (a) 해소)
- 시험 111개 통과(신규: `test_verify.py`, `test_device_tools.py`, 저장소 기록 시험), 시뮬레이터로 화면 시험 완료
- 보안 검토(security-reviewer) 반영: 설정 변경 응답 누락 시에도 기록 남김("확인 불가" 포함) · 통신 오류 시 링크 끊기(늦은 응답 혼입 방지) · 확인 창 뒤 권한 재확인 · 기록 실패 경고 · 권한 없는 시도 기록 · 되읽기 예외는 노랑 처리
- 검토에서 남긴 것: (a) [해소: 이중 입력으로 전환] (b) 통신 중 상단 [로그아웃]을 누르면 다음 사용자가 같은 소켓으로 보낼 수 있음 — 기존 `App.logout` 동작이라 이번에 안 고침

변경(2026-11-16)
- CIJ 탭 삭제: **TTO만 지원**(사용자 지시). 전송 실패·불일치 3회·만료 시 **빨간 신호등 창**(사유 표시)
- **작업 시작 자동 실행(사용자 지시)**: 전송 성공 + 수신 확인 초록이면 `~ST|06|`(Producing)로 장비를 준비 상태로 보내고 `~DR`로 확인(최대 5회). 이미 생산 중이면 보내지 않음, 초록이 아니면 시작하지 않음. 설정 변경에는 적용 안 함. `~ST` 형식은 매뉴얼 예제(`~ST|04|`)대로 `ngpcl.simple` 사용(기존 `state_change` 빌더는 구분자 한 개 더 붙어 쓰지 않음). **실장비 시험 필요**(상태 코드 06, 상태 전환 시간)
- 작업 시작 보안 검토 반영: 필드 없이 작업만 선택(`~JS`)하면 자동 시작 안 함 · 장비 상태는 생산 플래그와 코드 06 **둘 다** 맞아야 인정 · 통신 중 상단 [로그아웃] 차단 · 1차·2차 화면에 '자동 작업 시작' 안내. **실장비 첫 시험에서 `~ST` 인자가 목표 상태(06=Producing)인지 PackML 명령 번호(06=Suspend)인지 확인 필수**(명령 번호면 장비가 일시정지됨). 남은 것: `갱신 후 인쇄`는 되읽기 전에 `~PG`로 1장 인쇄(기존 동작), 작업자의 `인쇄 신호`는 이중 입력 없음(기존 정책 확인 필요)
- v0.3.1(실사용 시험 피드백): 필드 입력칸에 ①필드 이름 ②값 이름표 · 값이 비면 확인 창 · 되읽기에서 필드를 못 찾으면 '필드 이름 확인' 안내 · 결과 표 열 넓힘 · **통신 내용을 `comm_날짜.log` 파일로 저장**(문제 분석용). 시험에서 '필드 이름 칸에 날짜를 넣고 값이 빈' 입력으로 전송이 안 된 사례(JU 성공 응답이었으나 되읽기에서 필드 없음) — 실장비 통신 로그 확인 필요
